# KeyLab 路线图

> 本文件记录 KeyLab 从 0.2.0 起的开发方向。每一项都区分「已实现」「已模拟（标注来源）」「待实机验证」，避免把尚未完成的能力描述成可用。

## 版本总览

| 版本 | 状态 | 主要内容 |
| --- | --- | --- |
| 0.1.0 | 已发布 | 6 节课程、四选一测验、37 键虚拟键盘、MIDI 事件监视器、本地进度（v1 schema）。 |
| 0.2.0-beta | 当前（测试版） | 14 节课（A–G 七个模块）、任务类型扩展（sequence/together/rhythm/staff）、统一 MIDI 事件管线、设备档案、节拍器与真实时间戳节奏分析、进度 v2 schema + 导出/导入、103 项单元测试、SW 版本化缓存。SMK-37 PRO 与 iPad 实机未验证。 |

## 0.2.0 已实现能力

- **课程**：A 认识键盘（4 课）、B 音高与音程（2 课）、C 音阶（2 课）、D 和弦（2 课）、E 节奏（1 课）、F 五线谱（1 课）、G MIDI 入门（2 课），共 14 课基础；另新增 H 入门曲目（30 首经典曲）、I 手指技巧（20 条），合计 64 课。
- **曲目与技巧**：从 Pianio 的 CC0-1.0 公有领域内容中转写 30 首入门曲 + 20 条 Level-1 技巧；使用 `wait` 判分模式（弹错不重置、弹对当前音再前进），适配曲目跟弹。
- **任务类型**：
  - `sequence`：按顺序弹奏，含「回弹第一个音」的重启语义、错误时说明实际音与目标音的半音距离。
  - `together`：同时按住目标音，多按即报错，松开不计完成。
  - `rhythm`：跟随节拍器击拍，用真实时间戳映射到音频时钟做贪婪匹配，输出平均误差与稳定性。
  - `staff`：看谱在键盘上弹对应音符。
- **MIDI**：所有输入（虚拟键盘、计算机键盘、Web MIDI、未来的原生桥接）先规范化为统一事件，再进入同一判分管线；来源被显式标记为 `virtual` / `computer` / `webmidi` / `native`，UI 据此区分高亮与说明。
- **MIDI 实验室**：设备选择、事件日志（上限可调）、原始字节折叠、过滤/暂停/清空、按音状态面板、CC Learn（音量/节拍器音量）、设备观察清单、JSON/CSV 导出。
- **进度**：`keylab.progress.v2` schema，含 v1 自动迁移、连续学习天数、答题正确率、练习统计；JSON 导出/导入（含校验与预览，不执行任何代码）。
- **无障碍与移动端**：跳过链接、方向键演奏虚拟键盘、`role="status"` 局部反馈、≥44px 触摸目标、`safe-area-inset`、`prefers-reduced-motion`。
- **工程**：9 个测试文件共 105 项单元测试；`pages.yml` 部署前先跑 `node --test`；Service Worker 版本化缓存。

## 已模拟、不可当作实机能力

- **虚拟键盘发声**：是 Web Audio 合成音，不是 SMK-37 PRO 的本机音源。
- **虚拟 MIDI 事件**：屏幕琴键产生的事件来源标记为 `virtual`，仅用于教学与演示，不代表外接设备已连接。
- **原生桥接适配器**（`native-bridge-adapter.js`）：只预留 `window.KeyLabNativeMIDI` 接收入口，**尚未实现**真实 Core MIDI 数据通路。

## 待实机验证（SMK-37 PRO 尚未验证）

- 实际音符范围与八度按钮行为。
- 力度曲线、CC 编号、Pitch Bend 范围。
- USB / 蓝牙连接方式与系统权限流程。
- iPad / iPhone 上音频解锁、静音开关、后台切换的表现。

以上结论须在持有真机后逐项记录到 `docs/MIDI_ARCHITECTURE.md` 的设备档案与观察清单中。

## 0.3.0：iOS / iPadOS 原生桥接

目标：让 iPad 稳定读取实体键盘。

- 需要一个原生容器（iOS / iPadOS App 或扩展），通过 Core MIDI 读取设备。
- 原生侧把 MIDI 事件转发给网页前端（WebView 消息或本地 WebSocket 桥接）。
- 前端 `native-bridge-adapter.js` 已预留接收入口，但真实数据通路、权限、生命周期管理都需要原生代码与真机联调。
- **这不是当前纯静态网页已经实现的功能**，在实机验证前不会宣称可用。
