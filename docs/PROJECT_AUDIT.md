## 2. 当前实际功能

- 6 节中文课程（找 C、七个音名、半音全音、C 大调音阶、三和弦、MIDI 基础），每课一个按键序列任务，通过后手动点击「完成本课」。
- 37 键虚拟键盘（MIDI 48–84，C3–C6），Web Audio 合成音，触摸/点击发声。
- 乐理测验：音符、音程、和弦/音阶、MIDI 四类加混合练习，四选一，答后显示解释。
- MIDI 实验室：Web MIDI 能力检测、设备选择、Note On / Note Off / CC / Pitch Bend 日志、屏幕合成器开关。
- 本地进度：`localStorage` 的 `keylab.progress.v1`，保存完成课程、答题统计、按键次数、练习轮次、最近日期。
- PWA 清单、Service Worker 缓存、GitHub Pages 工作流、中文界面、响应式导航。

## 3. 发现的问题

严重度：**高** = 会造成数据丢失、错误状态或明显不可用；**中** = 明显影响体验或可维护性；**低** = 细节、无障碍与一致性问题。

### 3.1 数据与状态

| 编号 | 严重度 | 问题 | 影响 | 0.2.0 处理 |
| --- | --- | --- | --- | --- |
| D-01 | 高 | `practiceNotes` 每 3 次按键才写入 `localStorage`，页面关闭可能丢掉最后 1–2 次记录。 | 练习统计不准确。 | 改为防抖保存并在 `pagehide` / 隐藏时强制落盘。 |
| D-02 | 高 | `lastActiveDate` 使用 `toISOString()`（UTC）。 | UTC+8 的凌晨会把日期记成前一天，连续学习天数会算错。 | 改用本地日期键，并建立 `activityDays` 数组。 |
| D-03 | 高 | 进度结构没有版本号，也没有导出/导入。 | 后续新增字段或用户换设备时容易丢失进度。 | 新增 v2 schema、v1 迁移、JSON 导出/导入、导入预览与校验。 |
| D-04 | 中 | 课程完成后需要再点「完成本课」；练习通过后直接离开不会记录完成。 | 用户误以为已完成，实际未保存。 | 通过判定后自动记录完成，并显示明确状态。 |
| D-05 | 中 | `midiConnected` 只表示「选中了输入设备」，不检查设备 `state`。 | 设备已断开时界面仍可能显示已连接，违反「不伪装连接状态」原则。 | 改为依据 `input.state === 'connected'`，断开时清理状态并提示。 |
| D-06 | 高 | 实体键盘在按住时断开，`heldMidiNotes` 不会清理。 | 声音卡住、琴键高亮卡住。 | 断开时释放该来源的全部按音，并停止对应声音。 |
| D-07 | 中 | MIDI 监视器复选框状态在每次重绘后丢失。 | 用户设置反复被重置。 | 纳入设置并持久化。 |
| D-08 | 中 | 课程数量硬编码为 `0/6`、`06`，测验题数硬编码为「4 道题」。 | 增加内容后界面显示错误。 | 由数据和题库长度计算。 |

### 3.2 音频与输入

| 编号 | 严重度 | 问题 | 影响 | 0.2.0 处理 |
| --- | --- | --- | --- | --- |
| A-01 | 高 | 指针在窗口外释放、切换页面或切后台时没有兜底清理。 | 音符持续发声、琴键高亮不消失。 | 处理 `pointercancel`、`blur`、`visibilitychange`，统一释放虚拟输入与声音。 |
| A-02 | 中 | 两个手指按同一个琴键时，先松开一个就会移除高亮并停止声音。 | 多点触控状态错误。 | 以指针集合管理同一琴键，只在最后一个指针离开时发送 Note Off。 |
| A-03 | 中 | 音频启动是异步的，快速按下/松开可能在解锁后仍启动声音或产生竞态；同一音符重复触发没有明确生命周期。 | 卡音或漏音。 | 新音频引擎使用每来源 voice key、pending 状态和统一 `allNotesOff()`。 |
| A-04 | 中 | 鼠标右键/次要指针也会触发琴键。 | 误触。 | 只接受主按钮/主指针。 |
| A-05 | 中 | 实体 MIDI 使用 `onmidimessage` 只挂在选中的单个输入上，且没有原始字节、通道压力、Program Change 等处理。 | 教学信息不完整，设备切换时容易漏事件。 | 引入标准化 MIDI 事件层与适配器；补充 Program Change、通道压力、复音压力、实时消息过滤。 |
| A-06 | 中 | 虚拟键盘没有把点击位置映射为力度，也没有真实的原始字节。 | 无法用模拟事件解释 Velocity 与 MIDI 字节。 | 由点击纵向位置计算力度，并让虚拟输入走与硬件相同的规范化管线（明确标记 `source: virtual`）。 |
| A-07 | 高 | Service Worker 缓存名与预缓存列表不随资源变化更新，新增模块不会离线可用。 | 更新后可能白屏或加载旧代码。 | 版本化缓存、预缓存全部模块、导航网络优先回退离线页、更新提示条。 |

## 5. 技术风险

1. **iOS / iPadOS Safari 不提供 Web MIDI。** 这是系统级限制，网页代码无法绕过。0.2.0 只保证虚拟键盘、课程、测验、进度完整可用，并预留原生桥接适配器；不会显示虚假的实体连接状态。
2. **没有 SMK-37 PRO 实机。** 无法确认实际音符范围、八度按钮、力度曲线、CC 编号、Pitch Bend 范围、USB/蓝牙行为。设备档案中的 37 键与 C3–C6 只是常见假设，必须标注「未实机验证」。
3. **音频需要用户手势解锁。** 首次触摸/点击后才能稳定发声；iOS 静音开关、后台切换可能影响音频。已做手势解锁与页面隐藏时的释放，但仍需实机验证。
4. **没有构建工具。** ES Module 需要 HTTP(S) 环境，直接双击 `index.html` 无法运行。README 必须明确说明本地服务器。
5. **许可证。** 当前没有引入任何上游代码、乐谱、音频素材。MIT 只覆盖本仓库原创内容。dacapo / Pianio 尚未审查和移植，不能默认其课程与素材可复用。
6. **Service Worker 更新。** 旧缓存可能导致用户看到旧版本。已通过版本化缓存和更新提示条降低风险，但首次更新仍可能需要刷新一次。

## 6. 暂不开发的功能

以下功能在本阶段明确不做，避免用模拟界面冒充真实能力：

- 原生 iOS / iPadOS 外壳与 Core MIDI 桥接（需要 macOS、Xcode、Apple 开发者环境和实机）。
- 麦克风音高识别。
- MIDI 文件导入/导出、MIDI 输出到硬件。
- 账号系统、云同步、多人排行。
- AI 自适应学习推荐。
- dacapo / Pianio 代码或课程素材移植（先完成许可证审查）。
- 完整传统钢琴教材、复杂乐谱解析。
- 对 SMK-37 PRO 的硬编码映射。
